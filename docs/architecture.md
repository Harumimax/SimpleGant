# SimpleGant: архитектура MVP

## 1. Цель продукта

SimpleGant - это простой онлайн-сервис для создания диаграмм Ганта в стиле Excel.

Основной сценарий:

1. Пользователь регистрируется в сервисе.
2. Создает проект.
3. Настраивает таблицу задач.
4. Добавляет задачи, даты, исполнителей, статусы и вехи.
5. Редактирует диаграмму Ганта в интерактивном рабочем окне.
6. Делится публичной ссылкой на просмотр проекта.

Продукт не должен повторять MS Project. Цель MVP - дать простой и понятный инструмент для ручного планирования проекта в формате "таблица + временная шкала".

## 2. Роли и доступы

В MVP есть две роли доступа к проекту:

- владелец проекта;
- публичный зритель по ссылке.

Владелец:

- создает проект;
- редактирует проект;
- редактирует задачи;
- настраивает колонки;
- добавляет вехи;
- отмечает нерабочие дни;
- меняет порядок задач и вложенность;
- меняет даты задач на временной шкале.

Публичный зритель:

- открывает проект по постоянной публичной ссылке;
- не регистрируется;
- видит проект только в режиме чтения;
- видит все поля и колонки так, как их оставил владелец;
- может локально переключать масштаб между днями, неделями и месяцами;
- может локально менять вертикальную плотность строк;
- может временно скрывать дополнительные колонки без изменения проекта.

Публичная ссылка постоянная, не требует пароля и доступна любому, кто получил
ее от владельца. Публичный просмотр рассчитан на desktop; отдельный телефонный
интерфейс в MVP не требуется.

В MVP не нужны:

- команды проекта;
- приглашения пользователей;
- роли редактора;
- история изменений;
- real-time совместное редактирование;
- пароль на публичную ссылку.

## 3. Основные сущности

### Пользователь

Пользователь регистрируется по email и паролю.

Минимальные поля:

- `id`;
- `email`;
- `passwordHash`;
- `createdAt`;
- `updatedAt`.

### Сессия

Авторизация использует непрозрачный случайный токен в защищенной HTTP-only cookie. В базе хранится только SHA-256 хеш токена, поэтому утечка таблицы сессий не раскрывает действующие cookie.

Минимальные поля:

- `id`;
- `userId`;
- `tokenHash`;
- `expiresAt`;
- `createdAt`.

Сессия удаляется при выходе, а все сессии пользователя удаляются каскадно вместе с пользователем. Изменяющие запросы с cookie-аутентификацией должны проверять допустимый `Origin`.

### Проект

Проект сразу подразумевает диаграмму Ганта.

Минимальные поля:

- `id`;
- `ownerId`;
- `name`;
- `startDate`;
- `endDate`;
- `excludeNonWorkingDays`;
- `publicToken`;
- `createdAt`;
- `updatedAt`.

При создании проекта пользователь обязательно указывает:

- название;
- дату начала;
- дату окончания;
- применять ли единый календарь проекта, исключающий субботы, воскресенья и
  вручную отмеченные нерабочие дни из длительности задач.

Настройка `excludeNonWorkingDays` задается при создании проекта, по умолчанию
включена и применяется ко всем его задачам. В MVP она не редактируется после
создания: изменение настройки не должно автоматически сдвигать существующие
задачи.

### Колонка проекта

Колонки принадлежат конкретному проекту.

Ограничения:

- максимум 10 колонок;
- пользовательские колонки в MVP только текстовые;
- колонки можно переименовывать;
- колонки можно менять местами;
- колонки можно скрывать и показывать.

Колонки по умолчанию:

- `Название`;
- `Тип работ`;
- `Исполнитель`;
- `Длительность`;
- `Статус`.

Минимальные поля:

- `id`;
- `projectId`;
- `name`;
- `key`;
- `orderIndex`;
- `isVisible`;
- `isDefault`;
- `createdAt`;
- `updatedAt`.

### Задача

Задачи отображаются в левой табличной части и связаны с полосой на временной шкале.

Минимальные поля:

- `id`;
- `projectId`;
- `parentId`;
- `orderIndex`;
- `level`;
- `title`;
- `workType`;
- `assignee`;
- `comment`;
- `duration` (вычисляется для ответа API и не хранится отдельно);
- `status`;
- `startDate`;
- `endDate`;
- `color`;
- `isCollapsed`;
- `customFields`;
- `createdAt`;
- `updatedAt`.

`assignee` необязателен: задачу можно создать и сохранить без ответственного.
`comment` необязателен, хранит до 1000 символов и отображается в форме создания
и редактирования задачи. Это обычное поле задачи, а не
отложенный функционал комментариев-стикеров.

Ограничения:

- вложенность до 5 уровней;
- вложенные задачи можно скрывать и раскрывать;
- при скрытии дочерние задачи скрываются и в таблице, и на временной шкале;
- родительская задача автоматически покрывает диапазон дат дочерних задач;
- даты родительской задачи вручную не редактируются;
- задачи можно перемещать выше и ниже;
- вложенность можно менять кнопками и drag-and-drop.

Статусы фиксированные:

- `Ожидает`;
- `В работе`;
- `На паузе`;
- `Завершено`;
- `Заблокировано`.

Типы работ фиксированные:

- `Бизнес-Анализ`;
- `Архитектура`;
- `Системный анализ`;
- `Разработка`;
- `Тестирование`;
- `Интеграционное тестирование`;
- `Приемка`;
- `Релиз`.

В форме создания и редактирования задачи тип работ выбирается из выпадающего
списка. Существующее значение из старых данных можно сохранить без изменения,
но новые произвольные значения API не принимает.

### Веха

Веха отображается как вертикальная линия на всю временную сетку.

Минимальные поля:

- `id`;
- `projectId`;
- `title`;
- `date`;
- `color`;
- `createdAt`;
- `updatedAt`.

В MVP вехи:

- принадлежат проекту;
- не привязаны к конкретной задаче;
- имеют название;
- отображаются поверх временной сетки.

### Нерабочий день

Пользователь может вручную отметить нерабочие дни проекта.

Минимальные поля:

- `id`;
- `projectId`;
- `date`;
- `label`;
- `createdAt`;
- `updatedAt`.

В MVP нерабочие дни отмечаются по одному дню.

## 4. Логика дат и длительности

Даты задач хранятся с точностью до дня.

У задачи хранятся:

- `startDate`;
- `endDate`.

Отдельное поле `duration` в базе не хранится. Длительность вычисляется включительно
по `startDate` и `endDate` в соответствии с единой настройкой проекта:

- при включенной `excludeNonWorkingDays` учитываются только рабочие дни, то есть
  исключаются субботы, воскресенья и вручную отмеченные нерабочие дни проекта;
- при выключенной `excludeNonWorkingDays` учитываются все календарные дни;
- диапазон, целиком попавший на исключенные дни, имеет длительность `0`, но его
  даты и полоса остаются существовать.

При явном вводе длительности и одной граничной даты вторая дата рассчитывается
так, чтобы вычисленная длительность соответствовала введенному значению. После
перемещения или изменения размера полосы длительность пересчитывается из новых
`startDate` и `endDate` по той же настройке проекта.

При создании задачи:

- доступны поля `Начало задачи` и `Конец задачи`;
- если указаны обе даты, задача создается с указанным диапазоном;
- если указана только одна дата, вторая дата рассчитывается по явно заданной
  длительности или длительности по умолчанию;
- длительность по умолчанию - 2 недели;
- если указаны обе даты, они сохраняются без пересчета, а введенная длительность
  игнорируется и вычисляется заново по календарю проекта.

Настройка календаря проекта влияет как на автоматический расчет второй даты при
создании задачи или изменении длительности, так и на отображаемую длительность
любого явно заданного диапазона.

При ручном перемещении, расширении или сужении полосы задачи на временной шкале:

- пользователь сам задает нужный диапазон;
- `startDate` и `endDate` обновляются напрямую;
- даты не сдвигаются и не корректируются по календарю проекта;
- длительность пересчитывается для отображения с учетом настройки проекта,
  выходных и его вручную отмеченных нерабочих дней.

## 5. Рабочее окно

Рабочее окно проекта делится на две основные области:

- слева: таблица задач;
- справа: временная сетка.

### Левая область: таблица задач

В таблице отображаются:

- номер задачи;
- вложенность;
- пользовательские и системные колонки;
- кнопка раскрытия/скрытия дочерних задач;
- кнопка перехода к редактированию задачи.

Нажатие на название задачи, ее полосу на временной шкале или кнопку действия
сразу открывает форму редактирования без промежуточной карточки подробностей.

Кнопка в строке `Структура проекта` временно скрывает все дополнительные
колонки, оставляя номер и название задачи. Повторное нажатие возвращает
настроенный набор видимых колонок без изменения сохраненной конфигурации проекта.
В компактном режиме левая область сужается, а временная сетка занимает
освободившееся пространство.

Задачи можно:

- создавать;
- редактировать;
- удалять;
- перемещать выше и ниже;
- делать дочерними;
- выводить из вложенности.

### Правая область: временная сетка

Сетка визуально напоминает Excel.

Шапка сетки:

- месяц;
- номер недели;
- день.

Масштабы:

- дни;
- недели;
- месяцы.

По умолчанию используется масштаб `дни`.

Вертикальная плотность строк переключается отдельно от временного масштаба:

- `Обычно` — исходная высота строк;
- `Компактно` — высота уменьшена на 40%;
- `Максимум` — высота уменьшена на 70%.

По умолчанию используется режим `Обычно`. Настройка влияет только на локальное
отображение таблицы и временной сетки, не изменяя данные проекта.

На сетке отображаются:

- полосы задач;
- вертикальные линии вех;
- выходные дни;
- вручную отмеченные нерабочие дни.

Полосу задачи можно:

- перемещать по временной шкале;
- перетаскивать по вертикали для изменения порядка связанной задачи в таблице;
- расширять;
- сужать.

Вертикальное перемещение полосы и drag-and-drop строки используют одну модель
видимого порядка: после отпускания полоса и связанная задача остаются на одной
строке, а изменение попадает в общий локальный черновик.

Цвет полосы:

- по умолчанию одинаковый для всех задач;
- выбирается пользователем при создании и редактировании задачи;
- сохраняется в задаче и применяется к ее полосе на временной шкале;
- выбирается из фиксированной мягкой палитры на 10 цветов.

## 6. Сохранение изменений

В редакторе используется автоматическое сохранение.

Изменения выполняются локально на frontend:

- изменение дат;
- изменение порядка задач;
- изменение вложенности;
- изменение колонок;
- изменение цветов;
- изменение вех;
- изменение нерабочих дней.

После изменения frontend обновляет локальный Zustand-черновик и через короткую
задержку отправляет полный агрегат на backend. Сохранения выполняются
последовательно: ответ на более старую версию не должен перезаписывать новый
локальный черновик. Если во время запроса появились новые изменения, после его
завершения отправляется следующая версия.

Во время сохранения интерфейс показывает компактный индикатор без отдельной
кнопки. После успешной синхронизации индикатор скрывается. При ошибке черновик
остается локально, показывается причина и действие для повторной попытки.

При закрытии или уходе со страницы незаписанный текущий агрегат дополнительно
отправляется запросом с `keepalive`. Это страховка поверх регулярного autosave:
браузер не может гарантированно задержать закрытие вкладки до получения ответа.

## 10. Основные API

### Auth

- `POST /auth/register`;
- `POST /auth/login`;
- `POST /auth/logout`;
- `GET /auth/me`.

### Projects

- `GET /projects`;
- `POST /projects`;
- `GET /projects/:id`;
- `PATCH /projects/:id`;
- `DELETE /projects/:id`.

### Tasks

Защищенные owner-only endpoints задач сохранены для обратной совместимости и
изолированной отладки, но редактор после шага 14 не вызывает их при каждом
изменении:

- `GET /projects/:projectId/tasks`;
- `POST /projects/:projectId/tasks`;
- `GET /projects/:projectId/tasks/:taskId`;
- `PATCH /projects/:projectId/tasks/:taskId`;
- `DELETE /projects/:projectId/tasks/:taskId`;
- `PUT /projects/:projectId/tasks/order`.

`PUT /projects/:projectId/tasks/order` принимает полный набор задач проекта с
`id`, `parentId` и `orderIndex`. Backend проверяет полный состав, родителей,
циклы, непрерывный порядок и ограничение в пять уровней, самостоятельно
вычисляет `level` и применяет изменения транзакцией.

Удаление родительской задачи удаляет все ее вложенные задачи. Редактор сохраняет
порядок и вложенность через общий локальный черновик.

`PATCH /projects/:projectId/tasks/:taskId` возвращает актуальный полный список
задач проекта, потому что изменение дат дочерней задачи может изменить диапазоны
нескольких родителей. Если у задачи есть дети, backend отклоняет переданные
вручную `startDate` или `endDate`. Диапазон каждого родителя рассчитывается как
минимальная и максимальная из известных границ его потомков. Пересчет после
изменения дат, смены вложенности и удаления выполняется в одной транзакции с
исходной операцией.

### Project columns

Отдельный защищенный owner-only endpoint колонок сохранен для обратной
совместимости, но основной редактор сохраняет колонки в агрегате:

- `PUT /projects/:projectId/columns`.

Запрос передает полный упорядоченный набор колонок с названием и признаком
видимости. Backend сохраняет системные ключи, генерирует ключи пользовательских
колонок, запрещает удалять пять системных колонок, проверяет принадлежность
идентификаторов проекту, уникальность названий и лимит в 10 колонок. Создание,
удаление и изменение порядка выполняются одной транзакцией. Пользовательские
значения задачи принимаются в `customFields` только для актуальных
пользовательских колонок того же проекта и только как строки. При удалении
пользовательской колонки ее значения атомарно удаляются из `customFields` всех
задач проекта.

### Milestones

Отдельные owner-only endpoints вех сохранены для обратной совместимости, но
основной редактор сохраняет вехи в агрегате:

- `GET /projects/:projectId/milestones`;
- `POST /projects/:projectId/milestones`;
- `PATCH /projects/:projectId/milestones/:milestoneId`;
- `DELETE /projects/:projectId/milestones/:milestoneId`.

Backend проверяет принадлежность проекта владельцу, принадлежность вехи проекту,
дату внутри периода проекта и цвет из фиксированной мягкой палитры. Период
проекта нельзя сузить так, чтобы существующая веха оказалась за его границами.
В редакторе веха отображается именованной вертикальной линией через всю
временную сетку. Изменения в диалоге сначала попадают в общий черновик Ганта.

### Non-working days

Отдельные owner-only endpoints нерабочих дней сохранены для обратной
совместимости, но основной редактор сохраняет календарь в агрегате:

- `GET /projects/:projectId/non-working-days`;
- `POST /projects/:projectId/non-working-days`;
- `DELETE /projects/:projectId/non-working-days/:dayId`.

Дата должна входить в период проекта и быть уникальной внутри проекта. Название
необязательно. Период проекта нельзя сузить так, чтобы существующий нерабочий
день оказался за его границами. При включенной опции исключения выходных эти
даты пропускаются вместе с субботой и воскресеньем только при автоматическом
расчете границы новой задачи. Явно введенный диапазон, редактирование и
drag/resize не пересчитываются. На временной сетке такие даты выделяются
отдельным мягким цветом.

### Gantt

Основной запрос для редактора:

```http
GET /projects/:id/gantt
```

Возвращает:

- проект;
- колонки;
- задачи;
- вехи;
- нерабочие дни.

Сохранение состояния:

```http
PUT /projects/:id/gantt
```

Принимает обновленное состояние диаграммы или пачку изменений.

В реализованном контракте frontend передает полный набор колонок, задач, вех и
нерабочих дней. Новые объекты получают UUID на frontend, чтобы на них можно было
ссылаться внутри несохраненного черновика. Backend:

- проверяет владельца проекта;
- запрещает идентификаторы, занятые объектами другого проекта;
- проверяет системные колонки, лимит и уникальность названий;
- проверяет статусы, типы работ, цвета и пользовательские поля;
- проверяет родителей, циклы и глубину вложенности;
- самостоятельно нормализует порядок соседних задач и вычисляет уровни;
- игнорирует присланные производные даты родителей и пересчитывает их;
- проверяет даты вех и нерабочих дней внутри периода проекта;
- заменяет состояние проекта одной транзакцией и возвращает сохраненный
  агрегат.

TanStack Query хранит загруженный серверный агрегат. Zustand хранит рабочий
черновик, его локальную ревизию и признак несохраненных изменений. Все операции
редактора сначала меняют Zustand, после чего autosave последовательно отправляет
полный агрегат. Ответ сервера применяется к черновику только при совпадении
ревизии; более новый локальный черновик сохраняется следующим запросом. При
уходе со страницы выполняется дополнительная best-effort отправка через
`keepalive`.

Публичный просмотр:

```http
GET /public/projects/:publicToken/gantt
```

Возвращает read-only состояние проекта.

Ответ не содержит `ownerId`, `publicToken`, данные сессий, временные метки или
другие внутренние поля. Endpoint не требует cookie-сессии, доступен только для
чтения и имеет отдельное ограничение частоты запросов. Mutation-endpoints по
публичному токену отсутствуют.

## 11. Нефункциональные требования MVP

Ожидаемый размер проекта:

- до 100-150 задач.

Совместное редактирование:

- не требуется.

История изменений:

- не требуется.

Экспорт:

- не требуется в MVP.

Мобильная версия:

- не требуется в MVP;
- редактор и публичный просмотр ориентированы на desktop.

Язык интерфейса:

- русский.

## 12. Главные технические риски

Главный риск проекта - интерактивный frontend-редактор, а не backend CRUD.

Особенно важные зоны:

- синхронизация вертикального скролла таблицы и временной шкалы;
- горизонтальный скролл временной сетки;
- расчет ширины и позиции полос задач;
- drag-and-drop порядка задач;
- drag-and-drop вложенности;
- resize полос задач;
- пересчет дат родительских задач;
- отображение разных масштабов: дни, недели, месяцы;
- читаемость интерфейса при 100-150 задачах.

## 13. Рекомендуемый порядок разработки

1. Настроить базовый проект: frontend, backend, локальный PostgreSQL и Prisma.
2. Реализовать регистрацию и вход.
3. Реализовать CRUD проектов.
4. Реализовать создание проекта с датами начала и окончания.
5. Сделать первый статичный экран редактора: таблица слева, временная сетка справа.
6. Реализовать CRUD задач.
7. Отрисовать полосы задач по датам.
8. Реализовать изменение дат через drag/resize полос.
9. Реализовать вложенность задач.
10. Реализовать автоматический расчет дат родительских задач.
11. Реализовать настройку колонок проекта.
12. Реализовать вехи.
13. Реализовать нерабочие дни.
14. Реализовать кнопку сохранения изменений.
15. Реализовать публичную ссылку на просмотр.
16. Провести полировку UX и базовое тестирование.

- приглашение участников;
- роли редакторов;
- история изменений;
- undo/redo;
- зависимости между задачами;
- экспорт в Excel/PDF/PNG;
- комментарии-стикеры;
- редактируемые статусы;

- пароль на публичную ссылку;
