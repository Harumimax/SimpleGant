# SimpleGant Design System

## Назначение

Дизайн-система поддерживает интерфейс SimpleGant как спокойный рабочий инструмент для ежедневного планирования. Она должна сохранять высокую плотность данных, понятную иерархию и визуальную связь между таблицей задач, временной шкалой и остальными экранами.

Основная метафора — аккуратный рабочий лист: нейтральные поверхности, точные границы, единый хвойный акцент и минимум декоративных эффектов.

## Принципы

1. **Содержание важнее оформления.** Цвет и поверхности помогают читать структуру, но не конкурируют с данными.
2. **Одна система состояний.** Hover, focus, active, disabled, loading и error выглядят одинаково на всех экранах.
3. **Плотно, но не тесно.** Рабочие экраны сохраняют информационную плотность, а формы получают достаточно воздуха для спокойного заполнения.
4. **Структура через сетку.** Разделители и выравнивание используются функционально, особенно в редакторе Ганта.
5. **Доступность по умолчанию.** Видимый keyboard focus, контраст, семантические элементы и touch targets не меньше 44 px.
6. **Минимум движения.** Анимации используются только как обратная связь и отключаются через `prefers-reduced-motion`.

## Типографика

Основной стек:

```css
Inter, "Segoe UI Variable", "Segoe UI", ui-sans-serif, system-ui, sans-serif
```

- Page title: 28–32 px, weight 600, отрицательный tracking до `-0.035em`.
- Section title: 18–20 px, weight 600.
- Body: 14–16 px, line-height 1.5–1.7.
- Supporting text: 12–14 px, muted color.
- Табличные числа и даты используют `tabular-nums`.
- Заголовки используют `text-wrap: balance`, пояснения — `text-wrap: pretty`.

Не используйте uppercase и увеличенный letter-spacing как декоративный приём.

## Отступы и размеры

Базовая сетка — 4 px. Основные значения доступны как `--space-1` … `--space-16`.

- Внутренний отступ control: 12–16 px.
- Высота основной кнопки: 44 px.
- Высота текстового поля: 48 px.
- Отступ между label и полем: 8 px.
- Вертикальный ритм формы: 20 px.
- Page gutters: 16 px mobile, 24 px tablet, 32 px desktop.
- Максимальная ширина контента: `--container-content` (`70rem`).
- Максимальная ширина app header: `--container-app` (`80rem`).

## Радиусы и тени

- `--radius-control` (`8px`) — кнопки, поля, компактные элементы.
- `--radius-lg` (`12px`) — empty-state icon, крупные controls.
- `--radius-xl` (`16px`) — диалоги и основные content surfaces.
- Тени используются только для elevation: кнопка, input и dialog. Не добавляйте одинаковые тени каждой строке или карточке.

## Компоненты

Реализованные компоненты находятся в `apps/web/src/components/ui`.

### Button

Варианты:

- `primary` — основное действие страницы или формы;
- `secondary` — отмена и нейтральное действие;
- `ghost` — icon actions и малозаметные действия;
- `danger` — подтверждение необратимого удаления.

Одновременно в одном визуальном блоке должна быть только одна primary-кнопка.

### TextField

Всегда передавайте `label` и осмысленный `name`. Допустимы `hint`, `error` и ведущая иконка. Ошибка выводится рядом с полем и связывается через `aria-describedby`.

### Alert

Используется для ошибок запроса или формы, которые нельзя привязать к одному полю. Текст должен объяснять следующий шаг.

### EmptyState и LoadingState

Empty state предлагает одно понятное действие. Loading state повторяет структуру будущего контента и содержит скрытый текст для screen reader.

### Modal

Построен на нативном `<dialog>`, поэтому фон становится неактивным, а фокус остаётся внутри. На мобильном превращается в bottom sheet. Контент диалога должен использовать `.ds-dialog-panel`.

### Brand и AppHeader

`Brand` — единое отображение знака и названия. `AppHeader` — базовая оболочка авторизованной части; новые разделы должны расширять её, а не создавать новый header с нуля.

## Адаптивность

Контрольные ширины:

- 375 px — телефон;
- 768 px — планшет;
- 1024 px — ноутбук;
- 1440 px — desktop.

Правила:

- mobile-first для форм и списков;
- touch targets не меньше 44×44 px;
- вторичные колонки списка складываются под основную информацию;
- горизонтальная прокрутка разрешена только внутри временной шкалы Ганта;
- диалоги на телефоне открываются снизу и учитывают safe-area;
- строки с пользовательским текстом используют `min-width: 0` и truncate/wrap по контексту.

## Создание новых экранов

1. Используйте существующие токены; не копируйте hex-цвета из старых компонентов.
2. Сначала выбирайте существующие UI-компоненты.
3. Сохраняйте один `h1` и явное основное действие.
4. Добавляйте loading, empty и error состояния одновременно с основным содержанием.
5. Для навигации используйте `<Link>`, для действий — `<button>`.
6. Проверяйте keyboard focus, 375/768/1024/1440 и отсутствие глобального horizontal overflow.
7. Если компонент повторился в двух местах, оцените перенос в `components/ui`, но не создавайте API без реального использования.
